### 테이블 구성 및 데이터
- 작업지시에 데이터를 입력할 때 개통접수번호 또는 장애접수번호에 반드시 값 입력
- 개통접수번호와 장애접수번호 양쪽 모두에 값을 입력할 수는 없음
### 인덱스 구성
- 작업지시_pk : 작업일련번호
- 개통접수_pk : 개통접수번호
- 장애접수_pk : 장애접수번호

### 문제
데이터 모델에서 'Z123456' 작업자(작업자ID='Z123456')가 최근 한 달간 방문해서 처리한 작업지시 중 실제방문일자 역순으로 최근 10건만 출력하는 SQL을 작성하고, 최적 인덱스를 설계하시오.

### 개선 튜닝1
```
--인덱스 추가
작업지시_x1 : 작업자ID + 실제방문일자 + 작업일련번호


select /*+ index(a 작업지시_x1) leading(a) use_nl(b) use_nl(c) */
	*
from (
	select 작업일련번호, to_char(실제방문일자, 'YYYY.MM.DD') 실제방문일자,
		case when a.개통접수번호 is not null
			then '개통'
			else '장애'
		end 접수구분, 
		case when a.개통접수번호 is not null
			then b.고객번호
			else c.고객번호
		end 고객번호, 
		case when a.개통접수번호 is not null
			then b.주소
			else c.주소
		end 주소
	from 작업지시 a, 개통접수 b, 장애접수 c
	where 1=1
	  and a.개통접수번호 =(+) b.개통접수번호
	  and a.장애접수번호 =(+) c.장애접수번호
	  and 작업자ID = 'Z123456'
	  and 실제방문일자 >= to_char(sysdate - 30, 'YYYYMMDD)
	  and 실제방문일자 < to_char(sysdate + 1, 'YYYYMMDD)
	order by 실제방문일자 desc
)
where rownum <= 10;

```


> Q1. 아래 조건들의 차이점이 있는가?
> ```
> 1. and 실제방문일자 >= to_char(sysdate - 30, 'YYYYMMDD)
	  and 실제방문일자 < to_char(sysdate + 1, 'YYYYMMDD)
> ```
> ```
> 2. 실제방문일자 >= to_char(add_months(sysdate,-1), 'YYYYMMDD')
> ```
> ```
> 3. 실제방문일자 >= trunc(add_months(sysdate,-1))
> ```
> 
> 
> A1. 차이가 분명히 있다. 지금 시점을 '2026-0 7-31 16:00' 로 보고 차이점을 설명하자면,
> 
> 1번. 최근 30일(오늘 포함) 을 의미한다. >= '20260701' and < '20260801'이 된다.
> 2번. 한 달 전 오늘부터이다. >= '20260630'이 된다. 만약 입력 컬럼이 date 타입이고 조건문이 `add_months(sysdate, -1)` 이라면 >= 2026-06-30 16:30 을 의미한다.
> 3번. trunc()는 date 반환 타입이다. 컬럼이 varchar2(8)인 경우 암묵적 형변환을 한다. 컬럼이 date라면 >= 2026-06-30 00:00을 의미한다. trunc는 하루 전체를 포함한다고 생각하면 된다.

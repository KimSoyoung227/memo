### 인덱스 구성
- 장비_pk : 장비번호
- 장비_x1 : 장비구분코드
- 상태변경이력_pk : 장비번호 + 변경일자 + 변경순번

### 문제
데이터 모델에서 장비구분코드가 'A001'인 장비의 최종(=현재) 상태코드, 변경일자, 변경순번을 출력하는 최적 SQL을 작성하시오.

- 장비구분코드 ='A001'인 장비는 10건
- 결과집합을 장비번호 순으로 정렬
- 장비 테이블의 최종변경일시는 상태코드 변경과 무관
- DBMS는 오라클이며, 12c 이후 버전임

### 개선 튜닝1
```
select a.장비번호, a.장비명, b.상태코드 최종상태코드,
	to_char(b.변경일자,'YYYYMMDD') 최종변경일자, b.변경순번 최종변경순번
from 장비 a, 상태변경이력 b
where 1=1
  and a.장비번호 = b.장비번호
  and a.장비구분코드 = 'A001'
  and (b.변경순번, b.변경일자) = (select max(h.변경순번), max(h.변경일자)
						  from 상태변경이력 h
						  where h.장비번호 = b.장비번호)
order by a.장비번호;

```

### 보완할 점1
1. 위 쿼리는 논리적 오류가 존재한다. `Max(변경순번)` 과 `Max(변경일자)` 는 각각 독립적으로 계산된다. 따라서 서로 다른 행에서 나온 값일 수도 있다. 
   보통 **최종 이력의 판단 순서는 ORDER BY 변경일자 DESC 처럼 구성**한다.
2. `상태변경이력_pk (장비번호 + 변경일자 + 변경순번 )` 을 이용하지 못하고 있다.
3. `h.장비번호`와 조인하는 컬럼은 `a.장비번호`가 더 자연스럽다. 왜냐하면 최종적으로 필요한 것은 '장비별 최종 상태' 이기 때문이다. 그래서 드라이빙 테이블이 장비 테이블이기도 하다. `b.장비번호`로 조인한 들 논리적으로 틀린 것은 아니다. 이미 'a.장비번호 = b.장비번호' 로 조인했기 때문에 결과는 같지만 **옵티마이저 입장에서는 상관 서브쿼리의 기준이 헷갈리게 된다.** 

### 개선 튜닝2
```
--1안
select a.장비번호, a.장비명, b.상태코드 최종상태코드,
	to_char(b.변경일자,'YYYYMMDD') 최종변경일자, b.변경순번 최종변경순번
from 장비 a, 상태변경이력 b
where 1=1
  and a.장비번호 = b.장비번호
  and a.장비구분코드 = 'A001'
  and (b.변경일자, b.변경순번) = (select *
						  from (
							  select h.변경일자, h.변경순번
							  from 상태변경이력 h
							  where h.장비번호 = a.장비번호
							  order by h.변경일자 desc, h.변경순번 desc 
						  )
						  where rownum <= 1
						)
order by a.장비번호;

--2안
select a.장비번호, a.장비명, b.상태코드 최종상태코드,
	to_char(b.변경일자,'YYYYMMDD') 최종변경일자, b.변경순번 최종변경순번
from 장비 a, 상태변경이력 b
where 1=1
  and a.장비번호 = b.장비번호
  and a.장비구분코드 = 'A001'
  and b.rowid = (select rid
						  from (
							  select h.rowid as rid
							  from 상태변경이력 h
							  where h.장비번호 = a.장비번호
							  order by h.변경일자 desc, h.변경순번 desc 
						  )
						  where rownum <= 1
						)
order by a.장비번호;
```

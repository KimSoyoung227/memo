
>Q. 웹사이트에서 이벤트를 하려고 해. 사용자가 초마다 100명이 넘게 접속할 거야. 우리는 사용자별 정보를 가져와야하기 때문에 순번에 따른 pk시퀀스를 지정해줘야해.
>
>이런 경우에서는 java에서 시퀀스를 해주는 게 나아? 아니면 오라클 시퀀스를 이용하는게 나아? 


오라클 시퀀스의 경우 java에서 DB 접속을 여러번 하게 되므로 DB Call 트래픽 증가된다.
JAVA에서 시퀀스를 설정하는 경우 무결성이 깨질 가능성이 존재한다. JAVA에서 임의의 변수를 주고 ++하는 방법은 위험도가 높다.

따라서 JAVA보다는 오라클에서 시퀀스를 생성해서 동시성을 보장해주는 게 맞다.

###### 시퀀스 정의 쿼리
```
CREATE SEQUENCE EVENT_USER_SEQ
START WITH 1
INCREMENT BY 1
CACHE 1000
NOORDER;
```

###### JAVA 또는 PS/SQL에서 시퀀스 호출 쿼리
```
INSERT INTO event_user (
    event_user_id,
    user_id,
    created_at
)
VALUES (
    EVENT_USER_SEQ.NEXTVAL,
    ?,
    SYSDATE
);
```

이렇게 시퀀스를 `NEXTVAL`로 호출하면 JAVA 또는 PS/SQL에서 SELECT 문으로 다음 시퀀스를 가져올 수 있고, 특히 JAVA에서 DB Call은 1번으로 끝난다.

###### 다음 시퀀스 조회 쿼리
```
SELECT EVENT_USER_SEQ.NEXTVAL FROM DUAL; //시퀀스가 PK인 경우 운영 시퀀스를 함부로 테스트하면 안된다.
```

JAVA로 시퀀스를 설정할 경우 다음과 같은 문제도 고려해야 한다.
웹서버가 단일 또는 이중화가 되어 있으면 동기화 처리가 별도로 필요하다. 초당 100명 이상이 접속하는 상황에서는 특히나 더 위험할 수 있다.

위 시퀀스 정의 쿼리에서 `CACHE` 옵션으로 일부 대응은 가능하다.
`CACHE 100` 옵션을 사용하면 시퀀스 값 100개를 미리 메모리에 확보할 수 있다. 디스크성 작업을 하지 않아 빠르지만 도중 DB 재시작하는 변수가 생길 경우 번호가 일부 건너뛰어지면서 시퀀스가 고르지 않게 저장될 수 있다. 시퀀스를 무조건 ++ 하는 조건이 아니라면 충분히 사용할 수 있다.

>Q. Redis와 Oracle 디비를 사용할 경우, 어느 디비의 시퀀스를 사용하는 게 좋을까?

첫번째 질문과 함께 고려해 보면 PK 시퀀스는 Oracle이 더 적합하다.
`Redis INCR`도 가능하지만 JAVA에서 시퀀스를 설정하는 것 처럼 추가 운영 설계가 필요하다. 

만약 Redis에서 시퀀스를 생성했는데 Oracle에 데이터 저장 직전에 오류가 나면 어떻게 처리할 것인가? 

Redis는 빠른 게 장점이지만 이벤트 참여 데이터의 최종 저장소가 Oracle인 것을 고려해보면 PK 생성도 Oracle에 맡기는 게 무결성 측면에서 안전할 것이다.

만약 `Redis INCR`을 사용한다면 처리 역할을 나누는 게 좋다.
```
Redis  : 빠른 카운터, 선착순 제어, 중복 요청 방지
Oracle : 최종 참여 이력 저장, PK 생성, 정합성 보장
```

참고로 `Redis INCR`를 사용하는 경우는 아래와 같다.
```
이벤트 실시간 카운터
선착순 남은 수량 체크
초당 요청 제한
랭킹/임시 대기열
```
